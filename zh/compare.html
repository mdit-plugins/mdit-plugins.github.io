测量方法
  1. 正确性对比会用两个实现渲染同一段 Markdown，并在最小化归一化（属性顺序；仅当双方都按设计输出包裹标记和生成 id 时才归一化这些内容）后逐字节比较输出；对于未使用自定义渲染器的变体，还会比较解析后的 token 流——源码映射等 token 元数据对基于这些 token 的下游插件属于公共契约。其余每一处差异都会附带原因说明。
  2. 基准性能与复杂度缩放数据为交错采样结果的中位数，因此两侧在同一进程、相同负载下运行。语料为仓库提交的 markdown 文件：normal 是语法较稀疏的真实文档，heavy 是语法密集的文档；每种语料在三个规模下测量。
  3. 测试套件对比会把每个包的单元测试直接跑在参考实现上（用参考包替换插件入口）。参考包缺少对应功能的测试会归为功能缺失；只断言内部实现细节的测试会静默跳过、仅计入汇总；其余失败测试都代表两个包之间的行为差异。
  4. 每个正确性差异都归因到一个根因：当参考实现的输出或 token 流有误时（源码映射错误、嵌套缺失/错误、内容丢失或错位、安全问题）记为「参考包错误」；当双方只是对同一结果的表示方式不同时（等价的 token 形状、同样合法的不同输出、有意的语法或选项设计）记为「差异」。统计按根因计数，而不是按用例计数。
  5. 拟合指数基于对数坐标计算：约 1 为线性增长，约 2 为二次增长。各缩放系列针对参考实现已知的超线性路径设计。
  6. 包体积按发布到 npm 的文件计算：dist/**、README、LICENSE*、package.json，以及包 files 字段中列出的其他文件。参考包体积为已安装包目录的大小，不包含嵌套的 node_modules。
  7. 入口 gzip 为 ESM 入口 gzip 后的大小：本包为 exports 解析出的入口，参考包为 package.json 中的 module / exports.import / main 入口。

提示

对比工具链与 spec 位于 compare/。运行 pnpm run compare 刷新对比数据，pnpm run compare:sizes 刷新包体积，pnpm run compare:docs 重新生成本页数据。
